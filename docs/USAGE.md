# O-Cleaner 使用指南

完整使用说明。项目定位、核心能力与快速上手请看 [README](../README.md)。

## 一、快速开始

1. 确认已装 Python 3（命令行执行 `python --version` 能看到版本号即可）
2. 双击 **`start-ocleaner.bat`**
3. 浏览器会自动打开 `http://127.0.0.1:8770/`

> **那个黑色命令行窗口就是服务本体，清理期间不要关闭它。**
> 关闭窗口 = 停止服务，网页会变成连不上。全部清理完成后关掉即可。

想清理系统目录（Windows 更新缓存、系统日志等）时，用**管理员身份**运行：
开始菜单搜 `cmd` → 右键「以管理员身份运行」→ 执行

```
cd /d "你的 O-Cleaner 目录"
start-ocleaner.bat
```

命令行参数：

| 参数 | 作用 |
|---|---|
| `--port 9000` | 指定端口（默认 8770，被占用会自动往后找） |
| `--no-browser` | 启动时不自动打开浏览器 |
| `--scan-only` | 只打印一份文字版扫描清单，不开服务 |
| `--scan-only --drive D` | 扫描指定盘 |

自测（302 项断言，含真实删除与 HTTP 端到端）：

```
python -X utf8 tools\selftest.py
```

## 二、界面怎么用

打开后会自动扫描当前盘（默认 C:）。**默认不会删除任何东西，必须你自己勾选。**

### 选盘
顶部右侧是盘符卡片，显示每个盘的可用空间和占用比例。点一下切换。
每个盘的目标列表不同：

- **系统盘（C:）** 包含 `Windows\Temp`、更新缓存、Prefetch、Minidump 等系统项
- **数据盘（D:/E:）** 只有该盘真实存在的东西，不会列出 `D:\Windows\Temp` 这种空项
- **自定义目录** 在工具栏输入任意路径（如 `E:\GameCache`），会扫描其中已知的垃圾文件夹

### 清理范围
工具栏的「清理范围」决定列表包含什么：

| 选项 | 含义 |
|---|---|
| 当前盘 + 用户级缓存 | 除了本盘专属项，还包括与盘符无关的用户级缓存（uv / pip / 浏览器缓存等，位于 `%LOCALAPPDATA%`） |
| 仅当前盘专属项 | 只看和所选盘直接相关的项，例如 `D:\Temp`、`D:\$Recycle.Bin` |

**选了数据盘（D/E…）时，「仅当前盘专属项」是默认值。** 因为 `%LOCALAPPDATA%`
永远展开成系统盘上的用户目录 —— 这类项跟所选盘毫无关系，挂在 D 盘清单里只会让人疑惑
「D 盘为什么会有浏览器缓存」。它们本来就在 C 盘清单里，一个都不会丢。

（早期版本没做这个过滤，于是选 D 盘会看到「D 盘的 pip 缓存」「D 盘的 Chrome 缓存」，
而路径全是 `C:\Users\…`。这是用户实测反馈后修的，自检里有一条断言钉死这个不变量：
非系统盘的目标路径必须落在本盘上。）

### 自动发现（数据盘能用的关键）

预定义目标只覆盖常见系统位置（`Windows\Temp`、回收站等），但磁盘占用的大头
往往是**长尾的个人软件**。所以常规扫描还会主动在本盘顶层寻找
「被知识库识别为可清理」的目录 —— 这类项带橙色的「自动发现」标记。

实测某数据盘：从只有 3 个可清理项（`\Temp`、未完成分片、回收站）变成 11 个，
多出网盘缓存、音乐软件缓存、驱动包、Office 部署缓存、下载器缓存等，
**几十 GB 从「看得到」变成「可直接勾选清理」**。

自动发现的安全约束：

- 只接受知识库判定为**可清理**且置信度非低的候选；未识别的一律跳过（宁可少提示，也不猜）
- 排除回收站内部（`$Recycle.Bin\S-1-5-...` 这类 SID 目录没有解释价值）、
  `ProgramData`、`AppData`、`Windows` 等位置
- **排除 `Program Files` / `Program Files (x86)`** —— 那里面是程序本体不是缓存
- **排除「装的是程序」的目录**：见下面这条
- 同名的父/子目录只保留最外层，避免 `steam` 与 `steam\appcache` 同时出现
- 父目录本身就是可清理候选时，不再逐个推荐它的子项
  （否则下载目录下的剪辑草稿目录会被当成 8 个独立清理项推荐，
  而那里面是用户自己的作品）
- 最多 12 项、深度最多两层 —— 清单太长反而让人无从下手

#### 「这目录里装的是程序」怎么判断

自动发现是按**目录名**命中知识库的，而知识库的关键词是给缓存目录写的。
撞上安装目录就出事 —— 实测踩过两次：

- 某盘根下一个名字很短的目录（名字里带短词 `ps`）命中了 photoshop 规则，
  （关键词里有短词 `ps`），里面装的却是 **Adobe 系列软件的安装目录**
- `C:\Program Files (x86)\Adobe`、`C:\Program Files\Microsoft OneDrive`
  同样被判成「可清理」

所以加了一道只看**通用特征、不看名字**的判断（看名字正是出问题的原因）：

| 判据 | 说明 |
|---|---|
| 顶层有 `Uninstall*.exe` / `unins*.exe` | 安装器留下的卸载程序 |
| **两个以上「版本号形态」的子目录** | 年份（如 `Photoshop 2024`）或四段式版号（如 `WPS Office\12.1.0.x`） |

实测区分度：装机目录命中 2 个，
而下载目录与云盘临时目录都是 0 个。

刻意**不用**的两条判据（也是实测排除的）：

- 「顶层 .exe 数量」—— 下载目录顶层躺着 5 个 `setup.exe`，
  按数量算会把**下载目录**误判成程序安装，白白丢掉一个真正有用的候选
- 「子目录里有卸载程序」——下载目录下每个装过又留下的软件目录都带卸载器，
  同样会误伤

卸载程序只在**顶层**出现才算数。原则是：**宁可少提示，也不能把「卸载软件」
当成「清理缓存」推荐出去**。

### 一键预设
右侧「一键预设」，最常用的是**安全清理**：只选「删掉会自动重建」的项，
跳过回收站、着色器缓存和需要管理员权限的项。

| 预设 | 作用 |
|---|---|
| 安全清理 | 缓存与临时文件，最稳妥 |
| 深度清理 | 再加显卡着色器缓存、缩略图、崩溃转储、系统日志 |
| 开发者清理 | 只清 uv / pip 包缓存 |
| 只清回收站 | 只选回收站，可展开挑单个大文件 |
| 全部取消 | 清空勾选 |

### 看清再删
每张卡片右侧的 **`?`** 展开该类型的完整说明，四项：**是什么 / 能否重建 / 删除影响 / 建议保留**。
例如 pip 缓存的「建议保留」写的是「常用离线安装，或经常重装同一批依赖」。

### 自动全盘扫描（一键直达，默认展示全盘最大项目）

点击工具栏的 **`全盘扫描本盘`** 即可**自动开始扫描**，无需二次点击。
扫描完成后，视图默认直接呈现 **「全盘最大项目」**，按实际占用体积降序直观展现空间大头；
同时也支持按需切换到「本层目录」、「只看文件」或「全部可清理」。

### 细分查看：这个目录里到底哪块能删

在「全盘扫描」里点开一个目录的详情，底部有 **`细分查看：哪些能删`**。它把一个目录拆成两部分：

| | 内容 | 举例 |
|---|---|---|
| ① 可清理的缓存子目录 | 删掉会自动重建的派生数据 | `Cache`、`Code Cache`、`GPUCache`、`Service Worker` |
| ② 千万不要删 | 用户数据与程序本体 | 书签、密码、Cookie、`History`、`Extensions`、游戏资源包 |

**为什么需要它**：一个与浏览器同名的目录可能装着上百 GB 的东西，整体标成「可清理」会删掉书签和密码，
但只写一句「建议保留」你也不知道这上百 GB 里哪一块动了没事。所以这里逐个子目录给出体积和理由。

它会先判断目录的**真实身份**，再决定怎么说话 —— 这个区分很重要：

- **浏览器资料目录**：提示「这里有书签/密码」，缓存部分单独列出
- **游戏安装目录**：提示「这是游戏本体，不是垃圾，想回收请用 Steam 卸载」，可清字节固定为 0
- **未能确定身份**：明确写「工具不判断」，只摊开体积分布，不给任何结论

判定不靠目录名。实测有台机器上这种同名目录里装的是论文和 ComfyUI 归档，
只看名字就会误报「这里有你的书签和密码」—— 所以必须真的在目录里看到 `Cache` / `User Data`
这类结构才算浏览器资料目录。

### 确认与执行
点右下角红色「清理选中项」→ 弹出确认表格，逐项列出**确切路径、大小、文件数**，
中/高风险项和不可逆操作会红框警告，权限不足的项会被点名 →
点「确认删除」才开始。完成后报告**实际释放量**（不是预估）和跳过原因。

被浏览器、剪辑软件占用的文件会**跳过而不是报错**，并提示「关闭相关程序后重试」。

## 三、Steam 游戏库（读清单，秒级）

右侧「Steam 游戏库」面板**不扫描磁盘**，而是直接读 Steam 自己的清单文件：

- `steamapps\libraryfolders.vdf` —— 列出所有 Steam 库（可跨多个盘）
- `steamapps\appmanifest_*.acf` —— 每个游戏的名称、安装目录、体积、状态、最近游玩时间

实测：**30 余款游戏、数百 GB，0.6 秒读完**（对比全盘扫描 30-260 秒）。

面板显示：游戏数、Steam 记录的总体积、每个库的位置与占用；游戏列表可按
**「最久没玩」或「按体积」**排序，并直接标出 `某游戏 13.9 GB · 从没玩过`
这类信息 —— 这是「该卸载哪个」最直接的答案。每条都有「打开目录」按钮。

两个只有读清单才能做到的事：

**① 与扫描结果互相印证。** Steam 记录的体积（`SizeOnDisk`）是它自己算的，
可以拿来对照磁盘实际占用；面板还会列出**磁盘上存在但 Steam 已无记录的残留目录**，
这类「卸载不干净」的残留通常是最值得回收的空间。

**② 状态校验。** 读 `StateFlags` 位判断游戏是否真的装全了
（1=未安装、4=已安装、2=更新中等），不会把「更新到一半」的游戏当成完整安装。

> 要卸载游戏**请在 Steam 客户端里操作**（右键游戏 → 管理 → 卸载），
> 它会一并清理库记录，不留残留。本工具不会代你删游戏本体。

### Steam 游戏也整合在「全盘扫描」里（支持中文名显示）

不必在「磁盘空间」和「Steam 面板」之间来回对照：扫描时会读一次 Steam 清单与 `config/game-names.json` 映射表，
在占用树和 Steam 页面中直接显示中文游戏名：

- `荒野大镖客：救赎 2（Red Dead Redemption 2）`
- `天国：拯救 2（Kingdom Come: Deliverance II）`
- `巫师 3：狂猎（The Witcher 3: Wild Hunt - Complete Edition）`
- `底特律：化身为人（Detroit: Become Human）`
- `文明 6（Sid Meier's Civilization VI）`

游戏直接列入「全盘最大项目」与当前层列表，不再设独立生硬的「游戏等大项」分类，
也去掉了「第 N 层」等无关的内部层数标注，界面更加干净直观。
游戏本体一律标为**建议保留**（`cleanable=false`），「全部可清理」视图里绝不会误推游戏。
想补充或修改游戏中文名：直接编辑 `config/game-names.json`，纯显示用途，零副作用。

## 四、扫描速度：借用 WizTree（可选，支持一键安装便携版）

全盘扫描有两条路径，**装了 WizTree 就走快的那条**：

| | 方式 | C 盘 | D 盘 | E 盘 |
|---|---|---|---|---|
| 默认 | PowerShell 递归遍历 | 258 秒 | 33 秒 | 51 秒 |
| 加速 | 调用 WizTree 读 NTFS MFT | **21 秒** | **3 秒** | **4 秒** |

大约快 9 倍。原理是不自己解析 MFT（那需要管理员权限、要处理 USN 日志与碎片，
出错就是错报体积），而是调用 `WizTree64.exe` 的导出参数：

```
WizTree64.exe D:\ /export="%TEMP%\oc-wiztree-D-1234.csv"
```

### 新用户引导与跨设备便携化

首页右侧栏最上方设有 **「运行环境自检」** 面板，新用户或把文件夹拷到新电脑时一眼即可确认：
1. **Python 运行环境** 是否就绪
2. **管理员权限** 是否具备（未提权时说明影响范围）
3. **跨设备兼容** 变量与路径状态
4. **WizTree 加速组件** 状态：
   - 若系统已安装：直接就绪调用；
   - 若未安装：面板提供 **「一键下载 WizTree 便携版（约 7.5 MB）」** 按钮，从官方直接下载免安装便携版并解压至本目录 `portable\WizTree\`。

**可移动性关键**：解压后的 `portable\WizTree\` 随同整个 `O-Cleaner` 文件夹移动，
拷入 U 盘或传给其他设备时**随拷随用、免再次下载、免管理员权限、不污染注册表**。

### 明确标明第三方许可及声明

- **版权与许可**：WizTree 版权归 **Antibody Software Limited** 所有，个人使用免费（PERSONAL USE ONLY）。
- **非捆绑原则**：本项目分发包**不内置分发 WizTree 二进制文件**，下载动作完全由用户在本机自主发起。
- **商业与分发合规**：若开发者欲将 WizTree 随自身商业产品直接打包捆绑分发，需向官方购买 [WizTree Distribution License](https://diskanalyzer.com/distribution-license)。
- **导出文件用完即删**：导出的 CSV（C 盘约 120 MB、77 万行）解析进内存后立即通过 `finally` 彻底删除；即使进程被强杀，下次启动也会主动清除遗留文件，决不产生临时垃圾。

### 附带的好处：任意层级的「拆分二级目录」

WizTree 导出的 CSV 含**每个文件的完整路径**，而且目录行的体积已经包含全部子孙。
所以解析完就有一张常驻内存的「目录 → 体积」表，任意目录的子项拆分都是查表：

```
D:\某缓存目录                  → 17.9 GB
  └ webui                    → 14.9 GB   ▸ 可继续展开
      └ sd-webui-aki-v4.11…  → 14.4 GB   ▸ 可继续展开
          └ python           →  8.4 GB   ▸ 可继续展开
```

实测每层 **1–4 毫秒**返回，深度不受扫描树的层数上限约束 ——
这解决了「树只展开到第 5 层，更深的大项点不开」的老问题。

## 五、累积清理与换算

**这两块是合并在一个面板里的**（「累积清理与换算」）：

顶部是累计释放总量与清理次数；下面紧接着就是把总量换算成日常单位的卡片
（手机照片 / 1080p 电影 / 4K 电影 / 3A 游戏……），一眼就能感知「清出来的空间能干点什么」。

想深挖细节时展开「查看明细图表」，里面才是：

- **各盘分布** 每个盘各释放了多少
- **趋势图** 每次清理的释放量柱状图（左旧右新，鼠标悬停看详情）
- **按类别累计** 包管理器 / 浏览器 / 临时文件 / 显卡缓存……各占多少
- **贡献最多的项目** 哪些清理项贡献最大

数据存在 `history.json`（最多保留 200 次）。「最近清理记录」面板里可一键清空，
清空后累计统计一并归零。

## 六、换算单位（可自定义）

| 单位 | 折算基准 |
|---|---|
| 张手机照片 | 3.5 MB |
| 首 MP3 歌曲 | 8 MB |
| 份办公文档 | 256 KB |
| 部 1080p 电影 | 2 GB |
| 部 4K 电影 | 20 GB |
| 个 3A 游戏 | 48 GB |
| 小时 1080p 视频 | 3 GB |
| 个安装包 | 512 MB |
| 小时 4K 流媒体 | = 4K 电影的 1/3（表达式范例） |
| GB | 换算基准，不单独展示 |

顶部胶囊按钮可以只看某一个单位，或看全部。

### 怎么加自己的单位

界面里直接加：**名称** + **大小**（数值 + MB/GB/TB）→ 点「添加单位」。
不想手填就点「**填入范例**」，会自动填成「部 演唱会录像 = 8 GB」。

也可以直接编辑 `config/convert.json`。这个文件在代码注释里说明了每个字段，
重点是 `bytes_per_unit` —— 它既能写数字，**也能写引用其它单位的表达式**：

```json
{
  "id": "hour_4k_netflix",
  "label": "小时 4K 流媒体",
  "plural": "小时 4K 流媒体",
  "bytes_per_unit": "1/3 * movie4k",
  "note": "4K 流媒体约 7 GB/小时，这里用『4K 电影的 1/3』演示表达式换算",
  "category": "影音"
}
```

上面这段引用了 `movie4k`（20 GB），自动算出 ≈6.7 GB，不用手算。
`unlimited: true` 的单位（如 `gb`）不参与「装得下几个」的展示，只当换算基准。

改完 `config/convert.json` **刷新网页即可生效**，不用重启服务。

## 七、自定义规则（勾选固定项，一键套用）

规则不是「填路径」，而是**把你勾选的那一组清理项存下来**，以后一键复用。

用法：

1. 在主列表里勾选你想要的清理项（可以是任意组合，跨类别也行）
2. 在右侧「自定义规则」面板里给规则起个名字，例如「每周清缓存」
3. 点「保存当前勾选为规则」

保存后规则卡片上会显示：包含几个清理项、**按当前盘算能释放多少**、以及各项的名称标签。
四个操作：

| 按钮 | 作用 |
|---|---|
| 套用到勾选 | 把这条规则里的项重新勾上（不执行删除），你可以先核对再点底部清理 |
| 立即清理 | 直接按规则清理这批项，弹出确认框显示预计释放量后才执行 |
| 改名 | 重命名规则 |
| 删 | 删除规则（只是删规则，不影响任何文件） |

**保存后立即清理**：勾选面板里的这个选项后，点保存时会先问你一句
（显示将清理几项、预计释放多少），确认后立刻执行清理，一步到位。

几个设计细节：

- 规则**记录创建时的盘符**。在 D 盘创建的规则切到 C 盘后「套用/立即清理」会置灰，
  并标注「N 项不适用于当前盘」，避免用错盘的路径去删东西。
- 同名保存会**覆盖**原规则，不会重复堆积。
- 规则是「选择集」而不是清理目标 —— 所以它不会出现在主列表里，只在侧栏出现。
- 规则存在 `config/custom-rules.json`。

## 八、定时自动清理

「定时自动清理」面板：勾选启用 → 设间隔小时数（支持 0.25 = 15 分钟）→
选按哪个预设、哪个盘 → 保存。面板下方显示下次和上次执行时间。

**注意**：它依赖服务窗口处于运行状态，窗口关了就不执行。
如果关闭期间已过预定时间，重新启动后会立即补跑一次。

### 贡献规则前请先跑 linter

`config/filetypes.json` 是全盘扫描的识别知识库。**一条错误的规则会真的让用户删掉不该删的东西**，
所以在提交规则之前必须过安全闸门：

```
python -X utf8 tools/lint_rules.py            # 本地检查
python -X utf8 tools/lint_rules.py --strict    # 警告也视为失败（CI 用这个）
```

linter 会做六件事：结构校验、语义自相矛盾检测、关键词跨规则冲突、
**用真实识别引擎跑知识库自己的每个关键词验证归属**、文档与配置一致性、以及
列出所有「可清理」规则供人工复核。其中最有用的是第三和第四项 ——
它能抓出「同一个关键词被两条建议相反的规则共用」这类会让用户删错东西的冲突。

## 十、支持哪些盘 / 能不能换电脑用

**支持所有盘符**（C: 到 Z:），也可以扫描任意自定义目录。

路径全部使用 `%LOCALAPPDATA%`、`%USERPROFILE%`、`%DRIVE%` 这类变量，
**不写死盘符，也不写死用户名**，所以：

- 整个 `O-Cleaner` 文件夹拷到 U 盘 → 拷到另一台 Windows 电脑 → 双击 bat 就能用
- 那台电脑的盘符、用户名、可用空间都会自动识别
- 唯一要求：装了 Python 3（不需要 pip 安装任何包）

数据盘上不存在的系统项（如 `D:\Windows\Temp`）会被自动过滤掉，
前提是程序能判断该盘是否为系统盘（检查 `\Windows\System32` 是否存在）。

## 十一、安全设计

工具会**硬性拒绝**以下删除目标，即使 `config/targets.json` 被改坏也不会越界：

- 盘符根目录本身，以及在根目录直接删文件
- `Windows`、`Program Files`、`ProgramData`、`Users`、`Recovery` 等系统目录
- 任何层级出现的 `System32`、`SysWOW64`、`WinSxS`、`Installer`、`servicing`、`Boot`
- `$Recycle.Bin`、`System Volume Information` 目录本身（回收站走专用清理接口）
- 用户主目录 `%USERPROFILE%` 及 `%USERPROFILE%\AppData`

**不会触碰**：用户文档 / 图片 / 桌面、已安装程序本体、已下载的 AI 模型
（如 `.ollama\models`）、`Windows\Installer`、`WinSxS` 组件存储。

删除是**直接删除**，不经过回收站。执行前会有确认弹窗列出确切的路径和大小。

### 解析层的契约：原样返回，不替调用方猜形状

`run_ps()` 执行 PowerShell 后**原样返回**解析出的 JSON：脚本输出对象就是 `dict`，输出数组就是 `list`。

这条契约看着琐碎，但它对应的是一次**很隐蔽的线上缺陷**：早先这里写成「如果结果是数组就取
第一个元素」，而目录体积测量的 PowerShell 恰好返回 `[{path,size},…]` 数组。后果是细分查看里
**除第一个以外的目录体积全部为 0**，界面上显示成「浏览器缓存目录识别得对，但体积是 0 B」，
看起来像没扫到，实则是解析层把数组吃掉了。

教训写进了代码与自检：**解析层不替调用方猜形状**，需要归一化由调用方显式做。
`tools/selftest.py` 阶段六用一条断言把「2 个路径 → 2 个结果」钉死，防止它复活。

## 十二、常见问题

**Q：启动后网页打不开？**
看黑窗口里打印的「界面地址」那一行，端口可能不是 8770（被占用时会自动往后找）。

**Q：某个项目提示「需要管理员权限」？**
这是正常的，不是错误。`Windows\Temp`、`Windows\Logs\CBS`、更新下载缓存等
本来就需要管理员权限。用管理员身份重新运行 bat 即可。权限不足时
**同批次其它项仍会正常清理**，不会因为一项失败而中断。

**Q：提示「X 项被占用」？**
浏览器、剪辑软件、Python 进程正在使用这些文件。关掉相关程序再清理一次即可。

**Q：清理后游戏变卡了？**
如果清了「NVIDIA 着色器缓存」，游戏首次启动需要重新编译着色器，会短暂卡顿，
之后自动恢复。这是唯一副作用，不会损坏游戏。

**Q：修改配置要重启服务吗？**
不需要。所有 `config\*.json` 改完刷新网页即可生效。

**Q：怎么彻底重置？**
删掉 `history.json`、`schedule.json`、`config\custom-rules.json`，
再把 `config\convert.json` 恢复到默认内容，就是全新状态。
