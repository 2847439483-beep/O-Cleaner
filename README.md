# O-Cleaner · 磁盘清理助手

Windows 上的磁盘清理与空间占用查看工具，界面为浏览器中打开的本地网页。

- 只使用 Python 标准库，不需要 pip 安装任何依赖
- 不采集使用数据；除用户主动点击「下载 WizTree 便携版」外不发起网络请求
- 默认不删除任何内容，需要手动勾选并二次确认；删除目标受保护名单拦截

详细使用说明见 [docs/USAGE.md](docs/USAGE.md)。

## 主要能力

| 能力 | 说明 |
|---|---|
| 常规清理 | 预定义清理目标与一键预设；每项附带「是什么 / 能否重建 / 删除影响 / 建议保留」说明 |
| 自动发现 | 在所选盘顶层查找被知识库判定为可清理的目录，覆盖预定义清单之外的个人软件缓存 |
| 空间占用查看 | 按体积降序展示整盘占用并支持逐层下钻；可将目录拆分为「可清理」与「不可清理」两部分 |
| Steam 游戏库 | 读取 Steam 的清单文件（不扫描磁盘），列出已安装游戏、体积与最近游玩时间；游戏以中文名显示，标记为「可清理」，可一键删除整目录（带二次确认与存档提示） |
| 卸载残留 | 列出磁盘上存在但 Steam 已无对应记录的目录 |
| 资源包 | 用可替换的 JSON 数据补充「这是什么、能不能删」的说明；内置 5 个包，支持导入自定义包与从 GitHub 检查更新 |
| 自定义数据 | 换算单位、释义/结论覆盖、固定项规则可打包导出/导入（JSON），格式公开、逐项校验，可让 AI 按规范生成后直接导入 |
| 接入自有 AI | 可选。填入自己的 OpenAI 兼容接口，让 AI 解释单个项目、生成清理方案。AI 只能勾选候选，不能直接删除 |

## 运行要求

- Windows
- Python 3（代码未使用 3.9 及以上版本的语法与标准库 API；CI 环境为 Python 3.12）
- 查看清单、清理用户级缓存不需要提权；清理系统目录（Windows 更新缓存、系统日志等）需要以管理员身份运行

## 快速开始

1. 确认已安装 Python 3（命令行执行 `python --version` 能显示版本号即可）
2. 双击 `start-ocleaner.bat`
3. 浏览器自动打开 `http://127.0.0.1:8770/`

启动后会弹出一个命令行窗口，它是服务进程本身；过程中关闭该窗口会停止服务。

需要管理员权限时，在提权的命令行中执行：

```
cd /d "你的 O-Cleaner 目录"
start-ocleaner.bat
```

命令行参数：

| 参数 | 作用 |
|---|---|
| `--port 9000` | 指定端口（默认 8770，被占用时自动向后查找） |
| `--no-browser` | 启动时不自动打开浏览器 |
| `--scan-only` | 只输出文字版扫描清单，不启动服务（可配合 `--drive D`） |
| `--fullscan-only` | 只执行全盘扫描并输出占用树 |

## 清理范围

预定义目标覆盖常见位置，例如 Windows 临时目录、Windows 更新缓存、回收站、开发工具与浏览器缓存。提供五个一键预设：

| 预设 | 选中范围 |
|---|---|
| 安全清理 | 删除后会自动重建的缓存与临时文件 |
| 深度清理 | 在安全清理基础上加入显卡着色器缓存、缩略图、崩溃转储、系统日志 |
| 开发者清理 | uv 与 pip 包缓存 |
| 只清回收站 | 回收站内容，可展开挑选单个文件 |
| 全部取消 | 清空勾选 |

除预定义目标外，常规扫描还会在所选盘顶层查找被知识库判定为可清理的目录（界面中带「自动发现」标记）。判定规则与排除条件见 [docs/USAGE.md](docs/USAGE.md#自动发现数据盘能用的关键)。

## 空间占用查看

- **全盘扫描**：扫描所选盘的全部占用，默认按体积降序展示「全盘最大项目」，可切换「本层目录 / 只看文件 / 全部可清理」
- **逐层下钻**：从任意目录继续展开下一级，展开深度不受扫描树深度限制
- **细分查看**：将目录拆分为「可清理的子目录」与「不可清理的部分」，逐项给出体积与理由；会先判断目录的实际身份（浏览器资料目录 / 游戏安装目录 / 无法确定）再给出结论
- **Steam 游戏库**：读取 `libraryfolders.vdf` 与 `appmanifest_*.acf`，不扫描磁盘；游戏列表可按体积或最近游玩时间排序
- **删除游戏**：没在玩的游戏是最值得回收的空间。点开游戏 → 详情里「删除这个游戏」，确认弹窗写明删掉的是整个目录、存档通常在哪、以及「客户端里卸载更干净」的替代做法。删除接口只接受后端自己识别出的游戏安装目录，非游戏路径一律拒绝
- **扫描进度**：按真实阶段上报（读取 MFT 明细、解析、展开目录树、读取游戏清单、逐项识别）。能算出总量的阶段显示具体百分比；读 MFT、PowerShell 递归、读游戏清单这几步无法预知总工作量，改用流动条纹表示「正在进行」，不给出猜测的数字

## 界面布局与操作

页头右侧是**视图导航**（常规清理 / 扫描概览 / Steam 游戏库），高亮当前页，点击直达任意页
—— 「扫描概览」没扫过时点它会自动开始扫描。左侧自上而下是工具栏、磁盘概览与内容区，
右侧是侧栏，两栏各自独立滚动（互不带动）。

- 侧栏顶部有一条吸顶的**面板目录**，列出全部折叠面板；点一下就展开并定位到该面板
- 右侧面板默认折叠，点击标题栏展开或收起；展开状态记录在浏览器本地，刷新后保持；
  展开时面板自动对齐到侧栏顶部，正文从头往下读
- 按 `Esc` 返回上一级：在全盘扫描页逐层退回上一层目录，退到顶层后再按一次回到常规清理
- 扫描进行中按 `Esc` 不会打断扫描，界面会提示等扫描结束
- 文件被占用删不掉时，清理结果里会多出「一键查找占用进程」：它先确认文件是否真被占用，再列出**可能**占用它的程序。这一步只能是**候选**（Windows 没有公开接口能把文件句柄反查成进程），所以由你自己保存退出后重新清理，工具不代关进程

## 资源包

资源包是可替换的 JSON 数据，用来补充或改写目录/文件的「这是什么、能否重建、删掉有什么影响、什么情况该留」四项说明，并给出更贴近具体项目的中文名（例如把 Steam 库里的某个目录直接标成具体游戏名）。

- 内置包放在 `packs/`，共 5 个：Windows 系统项、常见软件缓存、游戏平台目录、游戏作品名、通用释义增强
- 界面「资源包」面板可查看已加载的包、启用/停用单个包、导入本地包文件、从 GitHub 检查更新
- 自定义包导入后写入 `config/packs-user/`，与内置包同 id 时覆盖内置版本
- 包格式、匹配语义与安全边界见 [packs/README.md](packs/README.md)

资源包不能改写「删不删」的结论：内置知识库已识别的项目，其 `cleanable`、`risk` 与归类一律以内置规则为准；资源包只对内置**未识别**的项目给出结论，其余情况只能补充说明文字。

## 自定义数据：导入、导出与 AI 生成

三类自定义数据——**换算单位**（把累计清理量换算成生活单位）、**释义/结论覆盖**
（改写某项的说明，或翻转「可清理」）、**固定项规则**（一组预选的勾选集合）——
可以打包成一个 JSON 文件整体导出 / 导入：

- 界面入口：「自定义规则」面板 →「导入 / 导出自定义数据」
- 格式规范、字段表与示例见 [docs/CUSTOMIZE.md](docs/CUSTOMIZE.md)
- 导入**逐项校验**：字段错误、重名、引用了不存在的清理项都会被跳过并逐条说明原因，
  好项照常收下；失败的导入不会留下半成品
- **支持 AI 生成**：把规范（或导出文件）发给任意 AI 助手，描述需求拿到 JSON 后导回。
  导入接口本身就是验收器——把返回的「跳过原因」再喂给 AI 修正，两三轮内即可全部收下
- 换机迁移：导出的 JSON 随人走；配合整目录拷贝（路径不含固定盘符）即可完整还原自定义状态

## 接入自有 AI（可选）

不填接口时该功能完全不参与工作，程序也不会发起任何相关网络请求。

- 支持任何 OpenAI 兼容的 `chat/completions` 接口：填写接口地址、模型名与 API Key
- 两个用途：解释单个清理项、按自然语言要求生成清理方案
- 方案只能从**已被内置规则判定为可清理**的项目里挑选，未知 id 会被丢弃并说明；AI 无法直接执行删除，勾选结果仍需人工确认后由底部按钮走同一套删除流程
- API Key 保存在 `config/ai.json`（已加入 `.gitignore`，不会进版本库）。界面只回显 Key 的尾 4 位，完整 Key 不会通过任何接口返回

## 删除目标的保护规则

以下目标不会被执行删除，即使 `config\targets.json` 被修改：

- 盘符根目录本身，以及在根目录直接删除文件
- `Windows`、`Program Files`、`ProgramData`、`Users`、`Recovery` 等系统目录
- 出现在任意层级的 `System32`、`SysWOW64`、`WinSxS`、`Installer`、`servicing`、`Boot`
- `$Recycle.Bin`、`System Volume Information` 目录本身（回收站使用专用清理接口）
- `%USERPROFILE%` 及 `%USERPROFILE%\AppData`

不列入清理建议的内容包括用户文档、图片、桌面文件、已安装程序本体、已下载的 AI 模型、`Windows\Installer` 与 `WinSxS` 组件存储。

删除为直接删除（不经过回收站）。执行前会弹出确认窗口，逐项列出路径、体积与文件数。被其它进程占用的文件会被跳过并在结果中说明；需要管理员权限的项目会被标注，同批次其余项目不受影响。

上述拦截规则配有对抗性用例，并已固化为 `tools/selftest.py` 中的回归断言，细节见 [SECURITY.md](SECURITY.md)。

## 换机使用

路径使用 `%LOCALAPPDATA%`、`%USERPROFILE%` 等环境变量，不含固定盘符与用户名。将整个目录复制到另一台 Windows 机器后可直接运行，盘符、用户名与可用空间会自动识别。要求目标机器已安装 Python 3。

## 常见问题

**网页无法打开**：查看命令行窗口输出的「界面地址」一行；端口被占用时会自动向后查找。

**提示需要管理员权限**：`Windows\Temp`、Windows 更新下载缓存等项目本身需要提权才能访问，以管理员身份重新运行即可；同批次其余项目不受影响。

**提示部分文件被占用**：浏览器、剪辑软件或 Python 进程正在使用这些文件，关闭相关程序后重试。

**清理后游戏首次启动变慢**：清理了显卡着色器缓存，游戏需要重新编译着色器，之后恢复正常，不影响游戏文件。

**修改配置后是否需要重启**：不需要，修改 `config\*.json` 后刷新网页即生效。

更多问题见 [docs/USAGE.md](docs/USAGE.md#十二常见问题)。

## 测试与贡献

仓库包含四道检查，均在 Windows 上运行，已接入 GitHub Actions：

```
python -X utf8 tools/lint_rules.py --strict     # 规则检查（8 项检查，警告计为失败）
python -X utf8 tools/_lint_selftest.py          # 验证 linter 自身有检出能力（缺陷注入）
python -X utf8 tools/selftest.py                # 功能自测（300+ 项断言，含真实删除与 HTTP 端到端）
node tools/cdp_check.js http://127.0.0.1:8770   # 浏览器渲染与交互检查（50+ 项断言）
```

断言总数随机器环境浮动（数据盘数量、磁盘内容密度、是否装 Steam 等），因此文档不写死单一数字；CI 上的实际条数见 Actions 日志。

`config\filetypes.json` 是占用识别的知识库，决定哪些目录会被判定为可清理。修改该文件必须通过 `tools/lint_rules.py`（CI 强制）。linter 会做结构校验、语义矛盾检测、关键词跨规则冲突检测，并使用实际识别引擎验证每条关键词的归属规则。

`packs\` 下的资源包同样受门禁约束：linter 会校验包结构、清单与文件是否互相对得上、正则能否编译、关键词是否过于宽泛、分类是否会在界面上排到末尾。`tools/_lint_selftest.py` 会向 linter 注入缺陷以确认这些检查确实生效。

贡献流程见 [CONTRIBUTING.md](CONTRIBUTING.md)，安全模型与漏洞报告见 [SECURITY.md](SECURITY.md)。
