# O-Cleaner 路线图（Roadmap）

> 规划基于当前基线 **v2.6**，按「近期 / 中期 / 远期」三档排列。
> 顺序不承诺时间表；实际取舍以「用户真实痛点 + 不破坏安全边界」为准。
> 欢迎通过 Issue 讨论优先级，贡献流程见 [CONTRIBUTING.md](../CONTRIBUTING.md)。

## 现状基线（v2.6）

- 空间分析：全盘排行 + 逐层下钻，快速扫描（1 层）+ 深层现场扫描；WizTree（MFT）可选加速；磁盘趋势折线（含清理活动悬停）。
- 清理执行：预设 + 自定义目录 + 排行勾选三种入口；嵌套去重；锁定文件预检整体中止；三态删除流程（原子改名 → 递归删除 → 残留如实上报）。
- 识别体系：内置 42 条规则 + 5 组资源包（172 条）；三层释义优先级；游戏库（Steam / Epic / GOG）与卸载残留检测。
- 辅助能力：被占用文件探测与进程候选提示；定时任务；AI 助手（自带 API Key，仅勾选不执行）。
- 工程：零第三方依赖（纯标准库）；单文件前端；中英双语界面；CI 两级流水线（快级每次推送 / 慢级定时与手动）。

## 近期（下一两个版本）

1. **GitHub Releases 发布通道**
   - 把 `dist/` 产物（免安装版 zip）挂到 Releases，配合版本标签自动出包；
   - 「检查更新」从对比版本号升级为读取 Releases 最新版说明。
2. **删除回执的可追溯性**
   - 每次清理导出一份「删除清单」（路径 / 体积 / 时间）到本地历史，可在界面回看；
   - 为「误删反悔」提供依据（高风险项已有回收站兜底，清单补足中低风险项）。
3. **大文件排行**
   - 现有排行以目录聚合为主，补充「全盘最大的 N 个单文件」视图（视频、镜像、安装包常是真正大头）。
4. **知识库长文本双语补全**
   - 界面框架已双语；内置规则与资源包释义的长文本继续补英文，消除英文界面下的中文残留。

## 中期

5. **自有 MFT 扫描引擎调研**
   - 评估不依赖 WizTree 的 NTFS 直读方案（读 MFT 需要管理员权限，需权衡权限门槛与收益）；
   - 目标：免第三方组件也获得秒级全盘扫描，WizTree 仍保留为可选加速。
6. **重复文件检测（哈希级）**
   - 同体积预筛 → 部分哈希 → 全哈希三级流水，控制大盘开销；
   - 只报告不自动删，交由用户勾选。
7. **「回涨」洞察**
   - 基于已有磁盘趋势数据，标记「清理后持续回涨的目录」，生成针对性建议（如某缓存每周回涨 2 GB）。
8. **资源包生态**
   - 包签名与信任分级（内置 / 已验证 / 未验证）；社区贡献包的提交流程；
   - 在线更新已有雏形，补齐完整性校验与回滚。
9. **本地模型接入（Ollama 等）**
   - AI 助手已支持自定义 Base URL；补一组本地服务预设与连通性自检，让离线机器也能用上释义能力。

## 远期

10. **exe 单文件发行**（此前暂缓，待 Releases 通道稳定后重启）
    - 内嵌运行时 vs 单 exe 的体积 / 启动速度权衡；SmartScreen 声誉积累策略。
11. **扫描快照对比**
    - 保存两次扫描快照，展示「这段时间什么变大了」，把趋势图从盘级细化到目录级。
12. **可移植性探索**
    - 抽象平台相关层（回收站、锁定探测、系统目录），评估 Linux / macOS 子集可行性；
    - 仅在核心体验不打折的前提下推进，不承诺。

## 非目标（明确不做）

- **不采集遥测**：不加入任何上传用户数据的行为，这是产品定位的一部分。
- **不做云端同步 / 账号体系**：保持「整个目录拷走即可迁移」的本地属性。
- **不代用户结束进程**：只列候选，杀进程的决定权永远在用户。
- **不引入第三方运行时依赖**：后端坚持纯标准库，例外须有压倒性理由并写入文档。

## 维护原则

- 版本节奏：功能修复随时本地提交；**门禁全跑 + 推送 + CI + 重建发行包只在版本更新时做**。
- 断言规模持续增长，文档与提交说明不写死断言总数，以「失败 0 即绿」为判定口径。
- 安全边界（永不删除清单、AI 只勾选不执行、资源包不可改写已识别结论）是硬约束，任何新功能不得绕过。
